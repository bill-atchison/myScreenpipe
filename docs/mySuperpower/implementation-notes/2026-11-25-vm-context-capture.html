Task 1 — Context store with ordering and freshness · ab235c5

Task 1 · Done · ab235c5

clear() keeps a tombstone (review fix)

Important fix. The first clear() stored None, which dropped the ordering: after a wake clear, a late post from before sleep was accepted and relabelled frames for up to 5 s. clear() now stores an empty-label tombstone that keeps (epoch, seq).

  • Tests: 11, not the plan's 10, because of the new clear_keeps_tombstone_ordering. Task 5's total becomes 23.
  • Tradeoff: a helper whose clock goes backwards (a VM snapshot revert gives a lower epoch) stays Stale until the Mac app restarts. That is inherent to the epoch design.
  • Interaction for Task 3: the wake hook calls this clear(&GLOBAL).

Task 1 · Change 1 — clear() tombstone

crates/screenpipe-engine/src/external_context.rs — clear. Committed ab235c5.

Before

pub fn clear(store: &ContextStore) {
    store.store(None);
}

After

pub fn clear(store: &ContextStore) {
    // Tombstone, not None: a late post with an old (epoch, seq) must stay Stale.
    store.rcu(|cur| {
        cur.as_ref().map(|c| {
            Arc::new(ExternalContext {
                app_name: String::new(), window_title: String::new(),
                epoch: c.epoch, seq: c.seq, received_at: c.received_at,
            })
        })
    });
}

Task 2 — Authenticated route POST /context/external · f17bde2

Task 2 · Done · f17bde2

Route registered with plain axum, not the oasgen builder

Plan deviation (repo mismatch). The plan said .post("/context/external", ...) next to /add. That is the oasgen builder, which panics at startup on a non-oasgen handler (server.rs:1154 documents this). The route is a plain .route(..., axum::routing::post(...)) just after .merge(server.into_router()).

  • Verified: it sits in the same chain as /add, before every layer (auth, CORS, privacy, trace) at server.rs:1565-1715. It is also kept out of the public OpenAPI spec.
  • Deferred to the final review: malformed JSON is rejected by axum (400/415/422) before the api_auth check; 8 clippy await_holding_lock warnings in the tests; and some route tests could be stronger.

Task 3 — Capture hook: guest labels for storage only · b76491b

Task 3 · Done · b76491b

Live timeline also shows the guest label (ruling on a plan-mandated finding)

Plan deviation. The plan said guest labels go to the DB insert only. That made the live timeline (hot cache) show Parallels Desktop for a frame the DB stores as MultiTerminal. PairedCaptureResult.stored_labels now carries the pair actually written to the row, and only push_to_hot_cache reads it.

  • Unchanged: every admission and processing decision (lock screen, include list, URL policy, DRM, bounds, meeting, OCR gate) still uses host values.
  • Semantic projection stays on host values. It can't be reached for Parallels frames: no parser matches, so the job ends with no_candidate before anything is stored.
  • Rulings applied: R2 (the wake clear goes in mark_recently_woke) and R1 (the wake tests take TEST_LOCK).
  • Extra file: packages/sdk/recorder-core needed stored_labels: None to compile.
  • Deferred: a Parallels-host miss on the focus monitor costs two lock-free loads, where the constraint says one (tens of ns, no allocation).

Task 4 — VM helper tools/vm-context-helper · e4ac34c

Task 4 · Done · e4ac34c

Owner-PID gate before every keyed post (security fix)

Important fix. The 403 retry re-read the key and posted again without re-checking who owned port 3031, a gap of a whole request round trip. The gate now runs inside PostAsync, so it guards every request. A test proves a "not ready" gate on the second call sends only one request.

  • Hardening ruled into the same round: the helper joins its own kill-on-close Job Object, so ssh children are born inside it; UseProxy=false and AllowAutoRedirect=false; the dead Down event is removed; the old Process is disposed; a test for not splitting surrogate pairs (R4); and a missing key file is logged clearly and starts no tunnel.
  • Round 2: a job setup failure is logged with the failing call and its Win32 error, then the helper exits (fails closed).
  • Not verified live: the real tunnel and a 204 (Task 5), backoff, lock/unlock, log roll, and the job-failure path.

Task 5 — Docs, final review, end-to-end check · ba8b958

Task 5 · Done · ba8b958

Heartbeats no longer drop the label (final-review fix)

Plan flaw, fixed. Every heartbeat got a new seq, and the hook required the stored seq to equal the one snapshotted before the screenshot, so steady-state VM frames intermittently fell back to Parallels Desktop. ExternalContext.since now moves only when the labels change (or on a new epoch or a clear); the snapshot and override_for compare since, while Stale ordering still uses (epoch, seq). A miss is still one load.

  • Also fixed in the wave: rustfmt (a CI blocker); the helper logs instead of crashing when session registration fails; an unidentifiable foreground clears the label; Warp is labelled Warp (its exe is preview.exe; ProductName is used only for generic exe stems); PERSONAL.md wording.
  • End-to-end (twice, Owner present): labels for MultiTerminal, Warp and chrome; 8 consecutive steady chrome frames kept the label; helper stopped, then frames say Parallels Desktop; VM locked, then frames say Parallels Desktop (the clear lands about 1 s after the lock).
  • Parked for the Owner: the generic-stem list has four speculative entries beyond preview; ProductName() catches only FileNotFoundException.
